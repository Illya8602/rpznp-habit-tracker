# 0001. Вибір Fastify як HTTP-рушія замість Express

- Статус: accepted
- Дата: 2026-10-10

## Контекст і постановка проблеми

Для проєкту Habit Tracker API необхідно обрати HTTP-фреймворк на платформі Node.js, який забезпечує строгу валідацію вхідних даних через схеми, високу швидкість обробки та чисту модульну архітектуру для проходження всіх етапів SDLC.

## Фактори прийняття рішень

- Вбудована валідація схем без накладних витрат.
- Висока пропускна здатність (критично для Завдання 5: профілювання та перформанс).
- Архітектура плагінів (ізоляція модулів та контекстів).
- Відповідність сучасним стандартам Node.js.

## Розглянуті варіанти

- **Express.js**: Класичний інструмент, але програє Fastify за швидкістю, має застарілу модель middleware та не має вбудованої валідації запитів (потребує сторонніх надбудов).
- **Fastify**: Швидкий роутер на базі radix tree, нативна підтримка JSON Schema для валідації та швидкої серіалізації, чиста модель інкапсуляції.

## Результат рішення

Обрано **Fastify**. Він надає готову інфраструктуру для валідації контрактів без зайвого коду та забезпечує необхідну продуктивність під навантаженням.
