# ADR 0004: Database Choice, Connection Pooling and Migration Strategy

## Status

Accepted

## Context

Для гарантії надійності, транзакційності та підтримки реляційних зв'язків між звичками та логами виконань потрібна персистентна СУБД.

## Decision

Використати PostgreSQL 16 із бібліотеками pg (пул з'єднань PgPool) та query builder Kysely. Автоматичну ініціалізацію схеми БД винесено безпосередньо у репозиторій при старті застосунку з обов'язковою перевіркою з'єднання (SELECT NOW()).

## Considered Options

1. Prisma ORM: Важкий генератор коду та додатковий рантайм-шар.
2. Kysely + PgPool (обрано): Повна типізація SQL, висока продуктивність, прямий контроль транзакцій.

## Consequences

- Плюси: Повна типізація запитів на рівні TypeScript, легкий рантайм, перевірка здорового стану БД на старті (fail-fast).
- Мінуси: Потрібно самостійно контролювати DDL-скрипти створення таблиць.
